# The 10 gap hunts, word for word from lens-items.json (made 21 Nov 2026). Read this whole file first.
# A finding of a hunt: lens "gap-<n>" (hunt 1 = "gap-1").
Hunt 1, Should-read matrix (missing links):
H1.1 List every setting, switch, plan gate, status and automation (from features.json + entities.json)
H1.2 For EACH one, list every other feature whose result it SHOULD change (the AI ideas, Today, counts, badges, reminders, messages, help, exports, the phone app)
H1.3 Then check in code that each of those really reads it
H1.4 A should-read with no read = finding
Hunt 2, Hidden conditions (works only if ...):
H2.1 For every automatic or "on" feature: write ALL conditions for it to reach one person (app installed, app linked by proven number, notifications allowed, phone maker rules, plan running, data filled in like birthday/phone, feature switch, version)
H2.2 Then check: can the owner SEE, per member, who will get it and who will not, and why?
H2.3 If the switch says "on" but some people silently get nothing = finding
H2.4 Count real reach on Crispy Curves (e.g. "birthday wish: on, reaches 1 of 40 members")
H2.5 Where reaching the person depends on the phone or the watch itself (phone maker sound, banner and battery rules that can change what the app asked for, a paired watch the phone must detect, a version check between phone and watch): mark that path "cannot be proven in the cloud, needs a real-phone check" and name what to look at on the device
Hunt 3, Did it happen? (proof of every automatic action):
H3.1 Every automatic send, reminder, push, digest, job: is there a record the owner (or HQ) can open that says it went, to whom, when, and why not when it did not?
H3.2 An automatic action with no record and no "why not" = finding (S2 when the owner believes it ran)
Hunt 4, Two features, one job (overlap and conflict):
H4.1 Find every pair of features that act on the same people or the same event (manual message vs automatic reminder; AI idea vs Today nudge; bell vs Today vs push; desk link vs phone proof)
H4.2 Check they agree: no double message, no suggestion to do what the system already did, the same count in both places, "done" in one is "done" in the other
H4.3 For every "done", "read" or "seen" mark: find where it is kept (this browser only, this phone only, or the server)
H4.4 Every other place that counts or sends the same items (a server push or daily summary, another device, another staff member, Today, the bell) must read that same mark
H4.5 a mark kept in one place while another place still counts the same item as waiting = finding
H4.6 Also the case where no mark exists at all: every list or count of items that point at a thing to act on (alerts, to-dos, a daily summary)
H4.7 When that thing is handled in its own page (reply sent, request settled, enquiry closed), does the item leave the list and the count in every place, server sends included, without anyone touching the item itself?
H4.8 An item that cannot learn its thing was handled = finding
Hunt 5, Built vs live (deploy state):
H5.1 For every feature in features.json: is it on main, deployed, behind a switch, or waiting for a migration?
H5.2 Compare code on main with what the live panel, HQ, website, phone app (Play version) and database really run (check the live version labels, list_migrations/catalog, switches)
H5.3 Any feature the notes or What's new call live that is not live = finding
H5.4 Output docs/system-map/LIVE-STATE.md (one row per feature: main / live panel / live DB / Play app), so he can always see what is really live
Hunt 6, Data a feature needs but nobody fills:
H6.1 For every field a feature depends on (birthday, phone, check-in phone, app link, plan dates, trainer, batch): how many Crispy Curves rows have it filled?
H6.2 Is there a screen that asks for it at the right moment?
H6.3 A feature that depends on a field most rows lack = finding
H6.4 For every input box (mobile number, name, date): feed it what a phone keyboard autofill or a paste really puts in (country code, spaces, dashes, digits in other scripts) and check that the length limit and the cleaning step together keep a valid value
H6.5 a box that cuts or refuses a real autofill = finding
Hunt 7, Old users, new rules:
H7.1 Every new flow that fixes something only for NEW installs or NEW members (e.g. the phone sign-in shows only on new installs): what happens to existing users?
H7.2 Is there a path for them?
H7.3 None = finding
H7.4 And the reverse: every "new since your last version" mark (dots, What's new, update notices, tips): what does a brand-new install or a brand-new member see?
H7.5 New marks on things that are not new to them = finding
Hunt 8, Silent fallbacks:
H8.1 By script first: docs/system-map/_tools/silent.mjs lists every catch block with file:line and three flags: logs? (calls a log, report or crash function inside), tells_user? (sets an error state, toast or alert inside), rethrows?
H8.2 Output _sources/silent.csv
H8.3 Helpers read ONLY the rows where all three are "no", plus every fallback value (?? null, || [], ?? 0) that sits in a file named in a journey that writes money, messages, alerts, sign-in or sync
H8.4 Everything else is counted in the grid as "filtered by script, N rows, not read" so the gap is visible
H8.5 For each: if this path runs, does the user (or owner, or HQ) learn anything?
H8.6 A silent path that hides a failed promise = finding
Hunt 9, Same fact, every place:
H9.1 For each fact a user sees (count of alerts, dues, plan end, birthdays today, members using the app): list every place it shows (panel, Today, AI, bell, push, phone app, HQ, export) and compare the values on the Crispy Curves data and the ugly data pack
H9.2 Any difference = finding
H9.3 For every number worked out from dates (not seen for N days, ends in N days, new this week, after a long gap): test the edges (day 0, someone who joined today, a plan that starts later, no visit yet, a gap of weeks)
H9.4 A number wrong at an edge = finding
H9.5 For every summary number shown with its own rows (a total, a target, a score): check it is worked out from those same rows, and when it is lower than last time the screen says why
H9.6 A summary that differs from its rows, or a drop with no reason shown = finding
H9.7 Open the files that work numbers out (engine, logic, lib, store), not only the screens that draw them
H9.8 For each number a screen shows above or beside its rows, find the function that makes the number and the function that makes each row
H9.9 if they are two different functions, compare them on a long-gap case
Hunt 10, Words promise more than the code:
H10.1 Every switch label, help article, What's new line and button that says what happens ("Members get a birthday wish", "Done items leave the bell"): read the code path end to end and confirm it happens for EVERY member the words cover
H10.2 Words wider than reality = finding (tie to the promise register)
H10.3 Include legal and privacy pages (data agreement, privacy notice, consent and sign-in screens), and check every way into the data, staff and direct database logins included
H10.4 Every notification, link and button: follow a tap to where it lands
H10.5 a tap that opens nothing, or a general page instead of the thing it names = finding
H10.6 Every button that can be greyed out or do nothing: the screen says why, next to it
H10.7 a disabled or silent button with no reason in view = finding
H10.8 Every label in every language the app offers (Hinglish runs longer): check in code it can wrap or shrink at 320 to 390 px wide (no fixed no-wrap, no min-width that cannot shrink, no crowded top bar)
H10.9 text cut off or pushed past the screen edge = finding
H10.10 Every picture the code points at (app and notification icons, badges, manifest and share images): is it the current brand and in the form the platform needs (size, one colour where the system draws only an outline)?
H10.11 An old-brand or wrong-form picture = finding
H10.12 To follow taps, find the one place that handles a tapped notification and list the pages it knows
H10.13 then list every kind of notification the code posts (on the phone and from the server) and check each kind is in that list
H10.14 A save button greyed out because nothing changed yet counts too: the screen must say it is already saved
H10.15 A promise that every look or change is recorded: routes that skip the app's code (the database's own login, its table editor, admin tools) leave no code to read, so look for a record the database itself writes (an audit setting, a job that pulls its logs)
H10.16 none = finding
